Car data flow on oldies

Dashwheel at 1251898a (upstream PR #56), before the fork's changes. Each source writes into its own store; there is no shared repository. Every consumer reads the stores it knows about and decides its own fallback order. Mapped from the code on 2026-10-23; file references are under app/src/main/java/com/openauto/dash/.

2 · How consumers read: by store, not by kind of data

There is no "give me speed" subscription. A consumer names the store objects it wants, and gets whole records from them; picking a field, and choosing between stores, is written inside the consumer. The only keyed lookup is SignalSources (string keys), used by the Signal Finder and learned signals.

3 · What adding a source costs

Because consumers are bound to stores, a new source is only as visible as the store it lands in.

Write into an existing store: free, if it can pretend

Deep OBD, the USB cable and the phone relay all end up in ObdData, so every OBD consumer sees them. The price is impersonation: Deep OBD has to fake CONNECTED, and only the fields ObdData already has can travel.

New unit adapter through CarSink: half free

CarFeed forwards doors, reverse, steering, headlights, volts and outside temperature into McuReader, CarBox and UnitSignals, so those reach every consumer. Speed and rpm stay in CarFeed: speed reaches only the drive lock chain, rpm nobody. Anything outside CarSink's nine methods (gear, fuel, odometer, handbrake…) has no way in.

New store: edit every consumer

A source with its own store (as CarBox and CarFeed were) is seen only by the consumers changed to read it. That is how speed ended up with ten different chains in section 5.

7 · Other quantities with more than one source

Fuel and range

FuelRange.kt:34-69: learned CAN byte → car app's litres ÷ profile tank → OBD fuel PID → back-computed from range. A 0 % CAN value with a range is dropped. OBD fuel is gated on "connected" in rememberFuelFrom but passed ungated (0 when disconnected) by CarFacts, FuelLog, StartupBriefing and CarCare.

Doors

Learned doors override built-in ones (LearnedSignals.kt:28). Built-in is last-writer-wins between the MCU frame 65 .. 0C 38, CarBox's door share and CarFeed.doors.

Reverse · headlights · steering

All last-writer-wins: reverse has four writers into CarBox._reversing; headlights five into UnitSignals._headlightsOn; steering three into CarBox.steeringWrite.

Supply voltage

OBD 0142 → ATRV, then replaced by the unit's own volts when they differ by more than 1 V with the engine running (ObdBluetoothManager.kt:886). The only store that feeds back into the OBD poll.

RPM

OBD only, for tiles and bar. GearEstimator falls back to CarBox's rpm. CarFeed.rpm is written on FYT and never read.

OBD itself

Route: USB cable → phone relay → unit's Bluetooth (AUTO). Deep OBD is a manual choice that stands the poller, DTC scans and auto-scan down and fakes CONNECTED.

8 · Capabilities: two systems

UnitCaps / Cap

26 caps, claimed per family, shown as ABSENT / LOCKED / READY / LIVE on the Settings head-unit card and in the report. Gates only FreeformBar and KeyTargets. QF claims DOORS, RADAR, CLIMATE… but its direct-to-store path never calls markUsed for them, so they never reach LIVE.

Ad-hoc flags

What actually gates tiles and alerts: CarBox.available, Tyres.available, RomPopups.available (canHide || CarFeed.provides), the add-sheet WidgetSource chips, PsaTripComputer.isPsa.

9 · Oddities worth comparing against

  • Values written, never read: CarFeed.rpm, UnitSignals.handbrake; UnitSignals.volts only through supplyVolts().
  • MTC bus is inert: the decoder's layout is never set.
  • Zero means unknown in ObdData: disconnect, demo end and Deep OBD down all reset to zeros, and a silent engine is published as 0 speed / 0 rpm.
  • Start paths are scattered: CarBox is started by QfBus and again by GearEstimator and MotorsportSkin; McuReader is held from about ten places; OBD starts from a Compose DisposableEffect, the unit bus from MainActivity.
  • Belt alert can be offered on a non-QF unit once doors are seen (CarFeed.provides(BELT)), though no sink carries a belt signal.
  • TPMS is the QF TPMS app only; the USB receiver is only power-cycled (TpmsReset).
  • DemoMode overwrites ten stores directly, each with its own restore path.
